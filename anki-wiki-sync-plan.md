# Anki Wiki Sync: plan and format spec

An Anki add-on (evolved from the Loopback Return Sync fork of
sajee05/anki_obsidian_sync, MIT) that syncs decks into an Obsidian vault as
a compact, queryable wiki: one page per deck, every card a linkable block.
It replaces the per-card mirror. Loopback (the Obsidian plugin) is a
separate project and is not touched.

Repo: `~/dev/anki-wiki-sync`. Installed into Anki as the symlink
`~/Library/Application Support/Anki2/addons21/anki_wiki_sync`. Anki must be
restarted to load it after code changes.

## Rules for every worker

- Python 3.9 compatible (Anki bundles 3.9): no `match`, no `X | Y` types,
  no `list[str]` at runtime; use `typing`.
- Anki-free modules (`wiki_schema.py`, `wiki_format.py`) import nothing
  from `aqt` or `anki` and are tested with plain `unittest`:
  `python3 test_wiki_format.py`, `python3 test_wiki_schema.py`.
- Vendor libs available at runtime and in tests: `yaml` (PyYAML),
  `markdownify`, `bs4`. In tests import `yaml` from the system or
  `vendor/`; never fixture a real deck.
- The sync owns its target folder exclusively and never writes outside it.
  It never deletes anything from Anki. It never reads or writes the Anki
  collection except through `mw.col` in `state_builder.py`.
- Style: no em dashes, no en dashes, no curly quotes, no emoji in code,
  comments, or docs. Sentence case headings. Exception: the page format
  below uses a single middle dot and a right-pointing character inside
  string literals that produce vault text; keep exactly those.
- Do not commit, do not `git add`, do not push. The architect commits.
- Report what you could not verify. Never adjust a test to make it pass;
  fix the defect or report it.

## Target folder layout

All inside the configured target folder (for example `<vault>/anki`), flat:

```
index.md          type: deck-index   tree of all synced decks
schema.md         type: sync-schema  how to read and query this folder
log.md            type: sync-log     append-only, one line per sync
decks.base        Obsidian Bases view over the deck pages
assets/           media copied from Anki (unchanged from upstream)
<deck-slug>.md    type: deck         one per synced deck
```

Deck slug: `slugify(deck_name.replace("::", " "))`, so `PHED163::Module 3`
is `phed163-module-3.md`. On collision, every deck after the first (sorted
by full name) gets `-<deck_id>` appended. `assign_slugs` is deterministic.

## Deck page format (schema_version 2)

```
---
type: deck
deck: "PHED163::Module 3"
deck_id: 1712345678
parent: "[[phed163]]"
subdecks:
  - "[[phed163-module-3-quiz]]"
cards: 42
notes: 40
lapsing: 3
tags:
  - phed163
  - stages
topics:
  - "[[classes/PHED163/Stages of Change]]"
  - "[[wiki/concepts/stages-of-change]]"
schema_version: 2
updated: 2026-09-07
sync_signature: 5f1c...
---

# PHED163 › Module 3

> [!info] Machine-managed by Anki Wiki Sync
> Rebuilt on every sync from the Anki deck named above. Do not edit this file; link to it. Every card is a block: `[[phed163-module-3#^n1725000000001]]`.

## Topics
- [[classes/PHED163/Stages of Change]]
- [[wiki/concepts/stages-of-change]]

## Weak spots
- 3 lapses · [[#^n1725000000001|Precontemplation: the client has no intention of changing...]]

## Cards
### phed163
- Precontemplation: the client has ==no intention of changing== in the foreseeable future. · Extra: Shares benefits only with permission. [↗](anki://x-callback-url/search?query=nid:1725000000001) ^n1725000000001
- What is decisional balance? → Weighing the pros against the cons of changing. [↗](anki://x-callback-url/search?query=nid:1725000000002) ^n1725000000002
### untagged
- ...
```

Rules:

- `parent` is present only when the parent deck is itself synced.
  `subdecks` lists synced children only; may be an empty list.
- `tags` is the union of display tags across the deck's cards. Display
  tags exclude `wiki::*`, `source::*`, `marked`, `leech`. Sorted.
- `topics` is sorted and deduplicated: wiki links resolved from `wiki::` and
  `source::` card tags through `WikiLinkResolver`, plus every vault note
  whose frontmatter `class:` equals (case-insensitive) any segment of the
  deck path, found through `TopicNoteIndex`. Links are full vault-relative
  paths without `.md`, in the form `"[[path]]"`.
- Each card appears exactly once, under its first display tag in sorted
  order, or under `### untagged`. Sections are sorted; `untagged` last.
  Within a section cards are sorted by their inline text.
- A card line is one line. `render_card_inline` joins the converted fields:
  cloze types: Text, then ` · Extra: <extra>` if non-empty; basic types:
  `Front → Back`; every other type: `Name: value` for each non-empty field
  joined by ` · `, skipping a field named Extra to the end as `Extra: ...`.
  Then: HTML table whitespace collapsed to single spaces, remaining
  newlines become `<br>`, a line starting with `- ` or `* ` inside the text
  becomes `• `, runs of spaces collapsed, trimmed. Cloze markup has
  already become `==text==` in the converted field (upstream converter).
- Every card line ends with ` [↗](anki://x-callback-url/search?query=nid:<nid>) ^n<nid>`.
  The block id is `n<nid>`, unique per page by construction.
- Weak spots lists cards with `lapses >= lapse_threshold` (default 2),
  most lapses first, then lowest ease, then text; each as
  `- <lapses> lapses · [[#^n<nid>|<first 80 chars of inline text>]]`.
  When none: `- No card in this deck has <threshold> or more lapses.`
- `sync_signature` is `sha1` over: `schema_version`, deck name, deck id,
  the sorted list of `nid:mod:lapses:ease` for its cards, the sorted
  topics, the sorted synced subdeck names, and the parent name. Deterministic.
  Two syncs with nothing changed produce byte-identical pages.
- `updated` is the local date.

## Index page

```
---
type: deck-index
decks: 3
cards: 61
lapsing: 4
schema_version: 2
updated: 2026-09-07
---

# Anki decks

> [!info] Machine-managed by Anki Wiki Sync
> One page per synced deck. See [[schema]] for how to read and query these pages.

- [[phed163|PHED163]] (0 cards)
  - [[phed163-module-1|PHED163::Module 1]] (19 cards, 1 lapsing)
  - [[phed163-module-3|PHED163::Module 3]] (42 cards, 3 lapsing)
```

Nesting follows the deck hierarchy; a synced deck whose parent is not
synced sits at the top level.

## schema page

`render_schema_page(target_rel_folder)` returns a static page (type
`sync-schema`, `schema_version`) that explains, for a person or an LLM
reading the vault: what a deck page is, the meaning of every frontmatter
field, that `^n<nid>` blocks are stable card anchors, how to query
(Obsidian search `path:<folder> term`, the `decks.base` view, an LLM
assistant asked to answer from this folder and cite `[[slug#^nid]]`), and
the rules (machine-managed, never edit, never capture flashcards from it).

## log page

`append_log_line(existing, line)` returns the file text with the line
appended; creates the frontmatter (`type: sync-log`) and `# Sync log`
heading when `existing` is empty. Line shape:
`- 2026-09-07T23:41 sync: 3 page(s) written, 0 deleted, 61 cards, 12 assets copied`.

## decks.base

Match the shape of the working file in the vault:

```
views:
  - type: table
    name: Decks
    filters:
      and:
        - file.folder == "<target_rel_folder>"
        - type == "deck"
    order:
      - file.name
      - deck
      - cards
      - lapsing
      - updated
    sort:
      - property: deck
        direction: ASC
```

## Module interfaces

### wiki_format.py (pure, W1)

```python
SCHEMA_VERSION = 2

@dataclass
class CardRecord:
    nid: int
    cid: int
    note_type: str
    fields_md: Dict[str, str]   # field name -> already converted markdown
    tags: List[str]
    reps: int
    lapses: int
    ease: int
    queue: int
    mod: int

@dataclass
class DeckRecord:
    name: str                   # full Anki name with ::
    deck_id: int
    cards: List[CardRecord]
    subdeck_names: List[str]    # synced children, full names
    parent_name: Optional[str]  # synced parent full name or None

def deck_slug(name: str) -> str
def assign_slugs(decks: List[DeckRecord]) -> Dict[str, str]        # full name -> slug
def display_tags(tags: List[str]) -> List[str]
def card_block_id(nid: int) -> str                                  # "n<nid>"
def render_card_inline(card: CardRecord) -> str                     # no trailing link or id
def compute_signature(deck: DeckRecord, topics: List[str]) -> str
def render_deck_page(deck: DeckRecord, slugs: Dict[str, str], topics: List[str], today: str, lapse_threshold: int = 2) -> str
def render_index(decks: List[DeckRecord], slugs: Dict[str, str], today: str) -> str
def render_schema_page(target_rel_folder: str) -> str
def render_base(target_rel_folder: str) -> str
def append_log_line(existing: str, line: str) -> str
def parse_frontmatter(text: str) -> Dict[str, Any]                  # {} when none; yaml.safe_load
```

### wiki_schema.py additions (pure, W1)

```python
class TopicNoteIndex:
    def __init__(self, vault_root: Optional[Path], exclude_rel: Iterable[str] = ())
    def topics_for_deck(self, deck_name: str) -> List[str]   # "[[path]]" links, sorted
```
Scans `*.md` under the vault root, skipping `.obsidian`, `.git`,
`node_modules`, `.smart-env`, `.trash`, and every folder in `exclude_rel`
(the sync target is always excluded). Reads only the frontmatter block.
Matches `class:` case-insensitively against each `::` segment of the deck
name. Never raises on an unreadable file.

### Anki-facing (W2, wave 2)

- `state_builder.build_anki_state` stays as is (per-deck notes with fields,
  tags, stats, mod).
- `state_builder.build_obsidian_state(target)` becomes: `{"base_path",
  "pages": {slug: {"deck", "sync_signature", "schema_version", "abs_path"}},
  "asset_files": set(), "other_files": set()}` from top-level `*.md` with
  `type: deck`. Non-deck markdown files (README, schema, index, log) are
  never deleted.
- `diff_calculator.calculate_diff` becomes deck-centric: `pages_to_write`
  (slug list: new, signature changed, or schema changed), `pages_to_delete`
  (deck pages whose slug is not expected), `images_to_copy`,
  `images_to_delete`, and a boolean `write_index` when anything changed.
- `executor` converts fields with `convert_html_to_markdown` per field,
  builds `CardRecord`/`DeckRecord`, resolves topics, renders through
  `wiki_format`, writes pages, index, schema (only if content differs),
  base (only if missing or differs), appends one log line per sync that
  changed something, copies media, deletes stale deck pages and orphan
  assets. All deletes stay inside the target folder.
- `__init__.py`: menu "Anki Wiki Sync" with Sync Now and Configure...;
  summary dialog reports pages written, deleted, cards, assets.
- A stub-runtime smoke test `test_sync_stub.py` fakes `aqt` and `anki`
  modules, feeds a fixture `anki_state`, runs the pipeline into a temp
  folder twice, and asserts: expected files exist, second run writes
  nothing, deleting a deck from the state deletes its page and nothing else.
