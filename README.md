# Anki Wiki Sync

## What it does

Anki Wiki Sync is an Anki add-on that syncs your decks into an Obsidian
vault as a compact, queryable wiki: one page per deck, and every card is
a linkable block inside that page. It replaces a per-card mirror with a
small set of machine-managed pages that a person or an LLM assistant can
read, search, and link into.

The sync is differential: it only rewrites a deck page when its content
has actually changed, and a run with nothing changed produces
byte-identical pages.

## Install

Install as a symlink or by building a `.ankiaddon` package:

- Symlink: link this repository's folder into your Anki add-ons folder
  (for example `~/Library/Application Support/Anki2/addons21/`).
- `.ankiaddon`: run `python build.py` to produce a versioned package in
  `dist/`, then install it from Anki's Tools > Add-ons > Install from
  file.

Restart Anki after installing or after any code change so the add-on is
reloaded. Once installed, the add-on adds an "Anki Wiki Sync" menu under
Anki's Tools menu.

## Configure

Open Tools > Anki Wiki Sync > Configure...

- Target folder: must be a subfolder inside your Obsidian vault (for
  example `<vault>/anki`), never the vault root. The sync owns this
  folder exclusively, so it must not be the folder containing your
  `.obsidian` directory.
- Deck allowlist: check the decks you want synced. Nothing syncs until
  at least one deck is checked; a fresh install syncs nothing.

## What gets written

Everything lives flat inside the configured target folder:

```
index.md          type: deck-index   tree of all synced decks
schema.md         type: sync-schema  how to read and query this folder
log.md            type: sync-log     append-only, one line per sync
decks.base        Obsidian Bases view over the deck pages
assets/           media copied from Anki
<deck-slug>.md    type: deck         one per synced deck
```

Each deck gets one page, named by a slug of its deck name (for example
`PHED163::Module 3` becomes `phed163-module-3.md`). A deck page looks
like this:

```
---
type: deck
deck: "PHED163::Module 3"
deck_id: 1712345678
parent: "[[phed163]]"
subdecks:
  - "[[phed163-module-3-quiz]]"
cards: 42
notes: 40
lapsing: 3
tags:
  - phed163
  - stages
topics:
  - "[[classes/PHED163/Stages of Change]]"
  - "[[wiki/concepts/stages-of-change]]"
schema_version: 2
updated: 2026-09-07
sync_signature: 5f1c...
---

# PHED163 › Module 3

> [!info] Machine-managed by Anki Wiki Sync
> Rebuilt on every sync from the Anki deck named above. Do not edit this file; link to it. Every card is a block: `[[phed163-module-3#^n1725000000001]]`.

## Topics
- [[classes/PHED163/Stages of Change]]
- [[wiki/concepts/stages-of-change]]

## Weak spots
- 3 lapses · [[#^n1725000000001|Precontemplation: the client has no intention of changing...]]

## Cards
### phed163
- Precontemplation: the client has ==no intention of changing== in the foreseeable future. · Extra: Shares benefits only with permission. ← [[classes/PHED163/Stages of Change#^recall-8f2a|Stages of Change]] [↗](anki://x-callback-url/search?query=nid:1725000000001) ^n1725000000001
- What is decisional balance? → Weighing the pros against the cons of changing. ← [[classes/PHED163/Decisional Balance|Decisional Balance]] [↗](anki://x-callback-url/search?query=nid:1725000000002) ^n1725000000002
### untagged
- ...
```

Every card is one line, ending in an `anki://` link back to that card
in Anki and a stable block anchor `^n<nid>` so it can be linked from
anywhere in the vault. Cards are grouped by their first tag, sorted, with
untagged cards last. A "Weak spots" section lists the cards with the
most lapses. The `topics` list links to vault notes about the deck's
subject, resolved from Anki tags and from any vault note whose
frontmatter `class:` matches the deck.

Each card also carries a `← [[note#^block|Note]]` link to the vault note
it was captured from: the exact highlight block when the card's extra
field holds an `obsidian://open` link (Recall writes one for cloze cards),
otherwise the note whose filename matches the card's `source::` or
`wiki::` tag. Open the backlinks pane on a class note and every card drawn
from it is listed. Never place links to the sync folder inside pages
managed by an LLM wiki plugin; its linter will replace them with stubs.

## How to query it

- Obsidian search: `path:anki` (or your configured folder name) to
  search only synced deck pages.
- The `decks.base` file is an Obsidian Bases view over every deck page,
  sortable by deck, card count, and lapses.
- Block links: from a topic note, link straight to a specific card with
  `[[slug#^n<nid>]]`, for example `[[phed163-module-3#^n1725000000001]]`.
- An LLM assistant can read the target folder, answer questions from the
  deck pages, and cite the specific cards it used with the same
  `[[slug#^nid]]` block links.

## Safety

- The sync never deletes anything from your Anki collection. It only
  reads from Anki and writes into the vault.
- It owns only its configured target folder and will refuse a folder
  that is your vault root.
- Inside that target folder it deletes stale deck pages (decks that are
  no longer synced) and orphan assets that are no longer referenced. It
  never touches `index.md`, `schema.md`, `log.md`, `decks.base`, or any
  file outside its target folder.

## Development

Run the pure-Python test suites with the standard library's unittest,
using Python 3.9 (the version Anki bundles):

```
python3 test_wiki_format.py
python3 test_wiki_schema.py
```

These modules import nothing from `aqt` or `anki`, so they run without
Anki installed.

## Lineage

Anki Wiki Sync is evolved from
[sajee05/anki_obsidian_sync](https://github.com/sajee05/anki_obsidian_sync)
(MIT licensed). Kept from upstream: the differential sync engine, the
HTML to Markdown converter, media handling, and the deck allowlist. The
per-card file mirror has been replaced with the one-page-per-deck wiki
format described above.
